# Plan Mode Architecture Rules (Non-Obvious)

## Two-Liberty-Server Constraint
- z/OS Connect (`BAQ<SHORT>`, port 9080/9444) hosts only `/api`. The frontend WAR goes to a **separate** Liberty server (`FE<SHORT>`, port 9081/9445). Any plan treating them as one server will break CORS and TLS config.

## DBB Build Pipeline Constraints
- `dbb-app.yaml` is the single source of truth for compile/link-edit parms. Adding a new language or deployment target requires a new `task` block here — not just adding source files.
- The `VanillaFrontend`, `ServerXmlPackager`, `ImsJavaBuilder`, and `zOSConnect` tasks are **custom Groovy tasks** defined in `.setup/build/groovy/CustomTasks.yaml` — they are not standard DBB tasks.
- Copybook dependency resolution path: `search:${WORKSPACE}/?path=${APP_DIR_NAME}/src/base/**/*.cpy` — copybooks must live under `src/base/` or they won't be found by impact analysis.

## IMS Java Bridge (IBTRAN) — High-Coupling Component
- `src/base/ims/cobol/IBTRAN.cbl` + `src/base/ims/java/` form a tightly coupled 31-bit COBOL ↔ 64-bit JVM bridge. Changing IBTRAN compile parms or the Java JAR (`ImsJavaBuilder` task) together can break IMS message processing silently.

## Customer Routing — Cross-Layer Coupling
- CICS vs IMS routing is decided by the **frontend** (strips `C` prefix → CICS; numeric only → IMS). The API layer exposes separate `/customers/{id}` and `/ims/customers/{id}` endpoints. Changing customer ID format requires coordinated changes in frontend JS, openapi.yaml, and COBOL commareas.

## Secret Scanning
- `detect-secrets` pre-commit hook uses `.secrets.baseline` as allowlist. Any new credential-like string must be audited and added to the baseline or the pipeline will fail.

## Certificate Lifecycle
- TLS certs are generated by `addcert.sh` + `gencert-sku.sh` using a RACF re-sign pattern (private key never leaves RACF). Cert validity follows CAB Forum SC-081 caps (200/100/47 days depending on date). Plan for periodic cert renewal.
